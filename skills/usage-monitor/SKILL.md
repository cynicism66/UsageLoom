# UsageLoom

当用户询问 AI 用量、额度或重置时间时，使用 UsageLoom 的 MCP 工具。当前 Provider Adapter 为 Codex。

## 工具选择

- 对“查看总览”“还剩多少额度”或“显示仪表盘”等综合问题，调用 `get_combined_report`。在支持 MCP Apps UI 的宿主中，该工具可以渲染合并的额度与 Token 仪表盘。
- 只询问 5 小时、每周等额度窗口或重置时间时，调用 `get_live_quota`。
- 需要按模型、项目、日期、缓存、输出或推理分析用量时，调用 `get_local_usage`。
- 需要查看最近或用量最大的任务时，调用 `get_recent_sessions`。
- 数据缺失、过期或互相矛盾时，调用 `diagnose_usage_sources`。

## 解释规则

1. 始终把账号支持的实时额度与本地 Token 统计分开说明。
2. 费用数值必须称为“API 等价费用估算”，不能称为“实际账单”。
3. 不得根据原始 Token 总量推测订阅额度消耗。
4. 如果额度来自本地 JSONL 回退而不是实时 app-server 响应，必须明确说明。
5. 优先使用隐私模式。只有用户要求任务级或项目级名称时，才请求相应 Session 元数据。
6. 不得请求、读取、显示或修改 OAuth Token 或 `auth.json`。
7. 不得调用登录、退出、切换账号、重置额度或其他账号变更操作。
8. 本地历史可能包含此前账号产生的会话，不得默认把它全部归到当前登录账号。

## 成功响应要求

先给出用户请求的关键数字，再说明：

- 统计覆盖的时间范围；
- 额度是实时数据还是本地回退；
- 是否存在扫描警告或价格覆盖缺口；
- 当解释可能受影响时，明确说明账号额度与本地历史的区别。

不要为了补全缺失字段而猜测额度上限、剩余 Token、账号归属或实际费用。
