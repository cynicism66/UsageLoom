# UsageLoom 0.6.4

本版改进实验性周容量估算的采样稳定性，并将参考范围限制在设置页。官方在线额度的百分比及重置时间仍按服务端返回值展示。

## 估算算法 v4

- 将至少 3 个百分点的额度下降组成一个非重叠区间，不再每下降 1% 就单独形成样本。
- 区间终点需有至少 2 分钟后的同账号、同套餐、同重置周期额度快照，以及足够新的日志索引扫描确认。时间等待是延迟保护，不是服务端计费完整性的保证。
- 使用累计加权比值：每周 API 等价值 = 有效区间累计已定价费用 × 100 ÷ 累计配对百分点；Token 容量使用同期有效 Token。不是把各段估值简单平均。
- 迟到日志和用户确认补归属后重新计算对应区间，替换旧样本，不重复叠加。账号、套餐、定价口径、重置、额度回升及停用边界分别处理；无法核实的区间不强行采样。
- 至少两段有效样本（合计至少 6 个百分点）后显示当前估算。仍采用有新数据时每 5 分钟批量计算，设置中可手动计算；手动计算不会跳过样本确认条件。

## 设置中的参考范围

“设置 → 每周容量估算”增加参考范围与样本成熟度。至少三个已定价、已确认区间后，显示各区间折算周价值的最小值至最大值；不足时说明样本条件。

参考范围仅出现在设置页。当前额度卡片与托盘小窗继续显示单个估算值，避免增加正文拥挤程度。

范围描述观测到的波动，不是统计置信区间，不承诺样本越多范围越窄。模型组合、缓存比例、缺失价格、其他设备使用及日志/额度上报时差都可能改变结果。样本成熟度表示积累程度，不是准确率保证；美元数值不是官方固定周额度、订阅余额或账单。

## 历史与升级

旧算法的最终估算保留为独立历史参考，不混入 v4 样本。新算法样本不足时，可继续显示带日期的历史结果；符合条件后切换到当前结果。已有时间快照可按新规则重新配对，缺失的快照不能补造。

升级前从托盘完全退出 UsageLoom，无需退出 ChatGPT/Codex。安装 MSI 或解压 ZIP 后启动。两种版本共用 `%LOCALAPPDATA%\UsageLoom\user-data\`，请保留此目录。不要删除数据库或重置采样来完成升级。
