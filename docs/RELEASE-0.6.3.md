# UsageLoom 0.6.3

本版包含 0.6.1–0.6.3 的修复，重点解决历史 Token、请求数与 API 等价估值被继承日志重复抬高的问题，以及窄窗口图表文字重叠。

## 用量统计修复

此前存在两层问题：重复父会话标记可能反复重置累计基线；复制到子会话的连续父历史，也可能被当作新的用量记录。两者都会抬高本地统计及其对应的 API 等价值，不代表官方在线额度本身变化。

现在父子边界仅在待确认阶段处理一次。继承前缀判定同时要求：

- 日志明确声明父会话，且能找到对应父日志；拒绝循环或冲突的祖先关系。
- 子日志开头的连续计数序列与父历史逐项匹配，比较累计和单次计数字段，而非只比较总数。
- 至少三个不同的有效累计值，父记录时间不晚于对应子记录。
- 仅排除匹配的历史前缀，保留分叉后的新增用量，且不替代原有子任务开始边界判断。

无关会话、短序列、缺失父日志或不匹配部分不会因此被去重。总量与分类不一致的记录仍不计费；只有原始计数字段完全一致时，它们才可作为连续历史的证据，不能充当有效计费基线。无法核实的历史仍有局限，不承诺所有日志都能完整还原。

## 数据迁移与升级

解析索引升至 **v7**。旧索引首次扫描会先验证原始日志，再创建 SQLite 备份并事务重建，原始日志不改写。备份位于 `%LOCALAPPDATA%\UsageLoom\user-data\backups\`，用于必要时恢复。

迁移后，之前重复统计的 Token、请求数及 API 等价估值可能明显下降，这是纠正历史统计，不是删除真实日志。未受影响的可识别记录保留原有归属；历史估算记录保留，不代表自动追溯校正全部旧估算。没有历史快照的区间不能补造。

升级前从托盘退出旧版，然后安装 MSI 或解压 ZIP。两种版本共用 `%LOCALAPPDATA%\UsageLoom\user-data\`，不要删除此目录。首次扫描可能较慢，请等待完成；迁移后避免用旧版本重新扫描，以免旧逻辑再次产生错误统计。

## 图表布局

窄窗口下历史趋势标题、指标按钮、说明使用独立行；更窄时总数与按钮分行，避免说明与按钮重叠。增加 380、520、900 DIP 往返缩放布局边界检查。
