# UsageLoom 0.6.6

本版是重要的数据兼容性更新，包含 0.6.5 的扫描隔离修复和 0.6.6 的分页日志接续支持。建议旧版用户升级；请保留原用户数据目录，不要清空数据库或通过全量重建处理分页迁移。

## 为什么需要更新

Codex 的旧会话日志迁移到分页格式后，文件可能被替换、缩短或重排；部分累计快照还可能使用不同的时间戳。源文件变化不等于已经记录的真实用量应该被删除。

旧版增量扫描遇到这类变化会中止整轮扫描，导致其他正常会话的新用量也无法更新。直接从迁移后的文件全量重建，则可能失去已不在当前文件中的历史明细。

本版改为保留既有计量记录，并在有可靠证据时接续物理文件的位置，而不是将两份历史相加或用较短的文件覆盖旧用量。

## 分页日志接续

- 识别 `session_meta.payload.history_mode: paginated`，校验会话身份和保留记录的单调 `ordinal` 序号。
- 同时核对完整累计计数及末次计数字段，不仅比较 Token 总数，不做跨会话的数值去重。
- 找到旧终点的时间和计数匹配后，仅追加能确认晚于旧终点的用量记录。
- 对迁移后改变时间的最终快照，仅在满足保守边界检查时将其视为物理索引接续证据，不再计入一次用量。
- 保留旧的计量明细、日期和账号归属；已经接续的文件可继续增量扫描并跨重启恢复。

## 无法确认的变化如何处理

无法找到可靠终点、身份不一致、序号不合法或计数不匹配时，保留旧索引和旧统计，不强行推算新增差额。该来源及同会话的相关来源暂缓重新推导，其他正常会话继续扫描。

界面会显示待核对文件数量。待核对来源的新内容尚未合并，并不代表这些来源已经完整恢复；旧记录也不会仅因文件变短而自动删除。此处理既避免历史丢失，也避免重复累计。

存在待核对来源时，暂缓生成新的周容量估算，保留已有历史参考结果，避免把不完整的本地用量与额度下降配对。这不影响正常会话的本地用量采集。

## 升级步骤

1. 从托盘完全退出旧版 UsageLoom，不需要退出 ChatGPT/Codex。
2. 安装 MSI，或者将 ZIP 解压到新目录后运行 `UsageLoom.App.exe`。
3. 保留 `%LOCALAPPDATA%\UsageLoom\user-data\`。MSI 与 ZIP 默认共用该目录；建议升级前另行备份整个目录。
4. 等待首次扫描完成，查看是否仍有待核对提示。不要为了消除提示而清空数据或全量重建。

首次使用或已经丢失旧索引的情况下，程序无法从分页文件恢复已被裁掉的逐次历史。此版本也不承诺修复此前已经发生且没有备份的数据覆盖。

- 133 项 C# 回归测试通过，覆盖改写隔离、同会话保护、旧明细保留、重定时快照、分页终点追加、跨重启增量和身份不匹配拒绝。
- 在独立数据库副本上验证接续，核对既有事件没有删除或改变 Token 数值；未将测试副本覆盖到正式数据库。
