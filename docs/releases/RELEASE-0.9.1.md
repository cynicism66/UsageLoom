# UsageLoom 0.9.1

## 更新内容

- **修复 Claude 容量参考一直显示“本机 Code 日志不完整”**：
  - Claude Code 自己写入的 `<synthetic>` 提示消息（如限额、中断提示）和附件记录，以前因为内容含有 `usage` 字样，被误当成“读漏的用量”，导致 5 小时与每周参考都无法出数。现在这些记录直接忽略。
  - 真正被跳过的记录会标注时间：带用量的回复解析失败时，用它自己的时间戳；文件损坏或超出读取上限时，用文件最后修改时间。只有可能落在当前 5 小时或本周周期内的缺口才阻止估算，很早以前的超大会话文件或个别异常记录不再一直挡住估算。时间无法确定的缺口仍会阻止估算。
- Claude 额度卡片标题由“Claude 桌面版”改为“Claude”，因为额度可能来自 Claude Code 状态栏，也可能来自桌面版。
- **托盘小窗显示估算**：Claude 卡片新增“5 小时参考”和“每周参考”两行。出数时显示“约 X 本机 Code Token”，样本不够时显示采样进度（如“采样 2／5 点 · 1／2 段”），其他情况显示原因；悬停可看说明。只显示 Claude 时，快照更新时间移到底栏，标题行只留“Claude”和套餐，原本只有设置按钮的底栏不再空着。

## 验证范围与已知限制

已运行以下检查：
- 核心回归，新增测试覆盖：
  - 系统消息与附件不算缺失；
  - 异常用量记录按自身时间标注；
  - 周期之前的缺口不阻止估算，周期内或时间不明的缺口仍然阻止。
- Release 桌面构建、中文和英文的全页面界面冒烟，以及数据来源设置检查；
- 托盘小窗检查：估算两行位于卡片内并标明所属窗口；只显示 Claude 时底栏显示快照时间。另在隔离数据目录中以只显示 Claude 的设置截图核对了布局。

修复前后的读取器都对开发者本机的真实 Claude Code 日志只读运行过一次，只统计数量，不输出内容：
- 修复前：16 处被跳过，估算被阻止；
- 修复后：只剩 3 处，即一个超出单文件上限的旧会话和两条计数矛盾的旧记录，最晚时间都早于当前周期，不再阻止估算。

安装包结构和升级规则经自动检查；真实安装与从旧版升级未在实机验证。

超过单文件 128 MiB 上限的会话仍不会读取，其中的用量不计入 Token 统计；统计页会继续提示“部分数据”。

## 升级

可在软件内检查更新。手动安装时，将同版本 MSI 和 `UsageLoom-install.cmd` 放在同一目录，从托盘退出 UsageLoom 后运行安装入口并确认 UAC。无需卸载或清理数据。
