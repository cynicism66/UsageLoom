# API 等价费用的计算依据

UsageLoom 展示本机日志按公开 API 文本价格折算的参考金额，不是订阅实际账单、账号余额或可用额度。目录版本为 `2026-09-07.1`；下表在 2026-09-07 核对。核对日期不是官方生效日期，官方未明确给出的起止日期保持未知。

## 公式与覆盖率

普通输入 = 输入 − 缓存读取 − 缓存写入。各类 Token 分别乘相应单价后除以一百万；推理已属于输出，不重复加价。缺失子分类价格不自动回退为普通输入价格。

定价覆盖率 = 已能定价的 Token / 全部有效 Token。它不表示账单完整性，也不表示特殊条件全部已知。全部缺价显示“暂不可估算”，部分缺价显示“部分估算”和缺口数量；真正的零单价与未知不同。

## 特殊条件

- Astra：单请求输入超过 272,000 时，输入及缓存 ×2，输出 ×1.5；已确认 Batch/Flex ×0.5，Fast ×2。
- Sol/Terra/Luna：单请求输入超过 272,000 时输入 ×2、输出 ×1.5；长上下文下缓存类别倍率未在当前核对范围内明确，因此该部分标为未定价，不猜测。
- GPT-5.4/5.5：官方描述为全会话的长上下文条件，必须有可靠的会话级判定，不能把本机累计输入当成单请求或全会话条件。
- GPT-5.4、5.4 Mini、5.5：明确使用区域处理端点时 ×1.1。不能根据用户所在国家或本地时区推断区域处理。
- 其他模型的非 Standard/Fast/区域倍率尚未核实则不套用；不将一种模型的规则泛化到全部模型。

解析器会在 `last_token_usage` 与本次增量一致时保存单请求输入规模，用于自动识别可验证的长上下文倍率。累计补差可能覆盖多个请求，不把末次请求的档位套到整段补差。若日志不能可靠恢复单请求输入、服务档位或区域条件，保留条件未核实说明；已知非普通档位但未核实其价格、或档位证据相互矛盾的部分保持未定价。工具调用、图片和音频独立费用不在本目录内。

## Fast、思考强度与证据

模式解析按同线程、同模型及有效时间匹配 `thread_settings_applied` 和 `turn_context`，不使用现在的全局设置倒推整段历史。父任务重放、显式其他线程的上下文、损坏或相互矛盾的字段不能成为 Fast 证据。正常模式切换不清空已有采样，也不改变 Token 数量或账号归属。

明确的回合档位与旧默认设置不一致、显式清空或上下文发生冲突时，旧默认档位失效。后续缺失档位字段保持未知，不能重新沿用旧 Fast；新的可靠任务设置才可重建默认依据。单回合显式档位只用于该回合，不自动提升为整个任务的设置。

若某线程存在明确属于它、但没有可靠生效时间的模式记录，无法安全确定模式切换位置，该线程的模式证据保守保持未知。Token、账号归属和额度采样仍保留，不以猜测时间边界补齐 Fast。

证据分为三类：

- **实际响应档位**：计价接口支持响应实际档位优先于请求设置；但当前已验证的本地日志并不提供可直接接入的响应实际档位，因此不会把本地设置标成实际响应已核实。
- **请求／设置档位**：日志明确请求了普通或 Fast 时，按相应公开 API 规则估算，并说明这只是设置证据。`priority` 与 `fast` 是同一档位，不重复乘倍率；实际响应可能不同于请求档位，见 [Responses 服务档位说明](https://developers.openai.com/api/reference/python/resources/responses/methods/retrieve)。
- **未知模式**：旧日志没有模式字段、记录不能可靠对应单次请求等情况，基础价只能作为条件估算，不能自动声称“普通模式已确认”。未知型号或未核实的特殊档位仍保留未定价 Token，不记为免费。

Fast 与 Ultra 是两个独立维度。Astra Fast 的 **API 等价单价为适用价格的 2 倍**；Ultra 思考强度本身不额外乘一个价格系数，推理 Token 已包含在输出中。Codex 订阅侧的 Fast 消耗规则与 API 单价不同，不能将订阅侧倍率再次乘进 API 费用。依据：[Astra 模型定价](https://developers.openai.com/api/docs/models/gpt-6-astra)、[Codex 速度模式](https://learn.chatgpt.com/docs/agent-configuration/speed)。

## 每周容量估算的可靠性

每周等价金额 = 有效采样区间的 API 等价金额合计 ÷ 同一区间已消耗的周额度百分点 × 100；Token 容量同样使用有效区间的 Token 合计。这个结果回答的是“按这些样本中的工作负载持续使用，一整周额度大约相当于多少”，不是固定套餐价值或保证还能使用的 Token。

混用不同模型、Fast／普通模式或思考强度时，仍可利用已核实的账号级额度变化，但不能仅凭账号级百分点反推出每个模型各自消耗了多少额度。详情展示的是**有效采样中的 Token 构成**，不伪造模式级扣费比例，也不把原来的 Fast 历史换算成普通模式的额度承诺。

“ⓘ”内的详情入口打开“估值依据与工作负载”，区分：

- **定价覆盖率**：有已核实类别单价的 Token 比例；高覆盖率不等于所有模式都已核实。
- **模式证据覆盖率**：实际响应、仅请求／设置、未知模式各占的 Token 比例。
- **条件估算部分**：依赖请求档位、基础价等条件的 Token；与定价缺口不是同一维度。
- **工作负载构成**：模型、模式、思考强度各自的 Token 分布，只包含参与估算的有效区间。

未知模式或混合模式不自行制造采样中断；账号、周期、重复记录、时间和日志完整性校验仍独立执行。无法核实的区间保留原因并等待后续证据，不靠放宽安全边界凑够进度。

托盘小窗说明使用简短的当前进度、阶段和证据摘要，不启用滚动条。完整采样规则与中断原因在详情内查看；没有有效样本或历史估值时也保留详情入口。历史金额与重新核验期间的旧金额明确标为参考，不冒充本轮新结果。

## 旧数据升级

模式元数据采用独立版本，不通过改价格目录版本或重建计数账本触发升级。首次补齐时先在线备份 SQLite，再在同一保存事务中更新必要字段；原始计数索引前缀、事件身份、Token 子分类、已有归属、用户确认和采样控制记录保留。副索引只记录白名单模式元数据，不保存提示词、回复、推理正文或凭据。

升级完成后自动请求重新核验当前估算，美元金额可能变化；Token 数量和额度百分点不因价格模式升级而改变。无法取得原始日志的历史仍保留，但不能凭空恢复其模式。旧缓存不会伪装成已重估：当前缓存标注等待重估；不可重放的历史参考标注模式证据未核实。

不同工具的估算价值可能不同，即使 Token 总数接近：价格目录的核对日期、长上下文判定、服务档位与缺价处理都会影响结果。UsageLoom 保留当前官方价格和已验证倍率，不以匹配其他工具的金额为目标。
