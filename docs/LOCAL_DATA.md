# 本地统计与安全重建

未登录也可以使用本地 Token 统计，界面显示“本地账户”。这只是本机统计模式的标签，不是 Windows 用户名或在线账号身份。历史记录可能来自不同时间使用过的账号，不能据此认定在线账户归属。

## 日常使用

- 在设置中选择包含 `sessions` 或 `archived_sessions` 的日志根目录。
- “扫描本地日志”建立或更新统计；文件变更会触发后台扫描，不依赖账号登录。
- “完整校验本地日志”校验已提交的历史前缀，不删除或重建统计。
- 美元金额是公开 API 单价的等价估算，不是实际账单；详见[价格说明](PRICING.md)。

## 日志被截断、替换或解析规则变化

发现历史变化时，普通扫描会保留旧统计并提示核对。若确认希望以当前仍存在的日志为准，可在“诊断与关于”选择“备份并重建本地统计”。

确认后，程序先扫描来源，再备份旧 SQLite 数据库，最后在同一个事务中替换统计与索引。不会修改原始日志。日志有解析警告、半行或读取失败时，不会替换旧统计；空日志目录也不会自动清库。

重建仅使用当前设置目录中的日志。其他目录和已删除日志对应的历史将从当前统计中消失，旧统计仍在备份中。相同身份、相同总量的事件保留已记录的本地日期；新识别的事件按本次解析结果建立日期。

## 备份位置与恢复边界

正常模式数据位于 `%LOCALAPPDATA%\UsageLoom\user-data`，备份位于其 `backups` 子目录，文件名为 `usage-before-rebuild-日期-随机标识.sqlite`。

备份通过 SQLite 在线备份生成，包含已提交的数据，不是简单复制可能缺少 WAL 内容的主文件。备份包含本地项目与来源路径等信息，请勿提交到 Git 或上传公开问题。当前不会自动删除备份，需留意磁盘空间。

目前尚未提供一键恢复备份入口。如需恢复，应先通过托盘“退出”完全关闭应用，保留当前数据目录的副本，再进行 SQLite 数据库恢复；不要在程序运行时直接覆盖数据库或单独删除 WAL/SHM 文件。原始 JSONL 已删除的内容不能由备份重新生成，备份只能恢复已保存的统计。

## 当前限制

- 已持久化字节游标，但文件变化后仍需重放标准化记录，尚非完整增量聚合。
- 复杂 fork、累计计数重置和超大规模历史仍需更多兼容性验证。
- 重建的核心事务已用合成测试验证，完整 UI 交互验收尚未完成。
